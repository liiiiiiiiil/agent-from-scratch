# 教程作者规范

本文件定义 `docs/tutorials/` 版本课程的写作与验收要求。教程是可独立学习、运行和验证的课程，不是版本更新摘要；代码与测试是事实来源，计划文档只描述意图。

## 内容原则

- 每课只讲当前版本相对上一版本新增的核心概念，并提供 `git checkout` / `git diff` 入口；不要提前描述后续版本行为。
- 先解释上一版的限制和本版要解决的问题，再解释实现、关键取舍及边界。
- 默认值、调用顺序、失败路径、返回值、配置项和命令必须与对应 tag 的实现一致。
- 突出一个教学主线；代码片段保持最小，完整实现通过文件路径和 tag 引导查看。
- 协议、安全、并发、预算、异常降级等主题要同时说明正常路径、不变量和刻意不解决的问题。

## 每课结构

原则上包含：版本/上下课导航；目标；前置条件与 tag 切换；改动文件表和 `git diff --stat`；问题、概念、流程与数据结构；实现拆解；设计选择与边界；可运行示例；测试命令与验收点；本版特性、下一课预告和代码索引。确实不适用的章节可合并，但学习链路不能中断。

## 同步与验收

完成版本时同步 README（中英文）、教程索引、操作手册、CHANGELOG、`pyproject.toml` 版本信息，并检查链接、代码片段、命令、协议描述和测试覆盖。运行时文档示例优先使用仓库 API 与标准库；开发工具（如 pytest）应同时给出仓库原生 smoke test 方式。教程结构检查器位于 `scripts/check_tutorials.py`。
